1. PRISMA SCHEMA (packages/db/prisma/schema.prisma)
   - GateStatus enum: PENDING / VERIFIED / EXPIRED / FAILED / CANCELLED
   - AdProvider model: name, type (default CUSTOM), description, enabled, archived,
     priority, configuration (JSON), relations to snippets + gates, indexes
   - AdSnippet model: providerId (optional, onDelete SetNull), type (default HTML),

   - MonetizationGate model: sessionId + userId (Cascade), round, unique publicToken,
     status (default PENDING), unlockAt, expiresAt, verifiedAt, attempts, code, codeHash,
     codeExpiresAt, providerId (SetNull), snippetIds (JSON), events relation, indexes.
     Round is stored so a player who already verified for a round is never re-gated.
   - MonetizationEvent model: optional gateId (Cascade), optional sessionId/userId
     (SetNull), type, status (default "recorded"), metadata (JSON), createdAt, indexes
   - Back-relations added to Session (monetizationGates, monetizationEvents) and User
   - `prisma generate` ran successfully. `prisma db push` CANNOT run in this environment

2. BACKEND: Monetization Core Service (apps/api/src/services/monetization.ts)
   - Read + validate all "monetization.*" settings (fallback defaults, clamped ranges)
   - generatePublicToken(): 24-byte crypto-random hex (never DB ids on public pages)
   - generateVerificationCode(): crypto.randomInt numeric, or crypto-random alphanumeric
     (no ambiguous chars); server-side constant-time comparison (sha256 codeHash)
   - getOrCreateGate(): creates a gate for an eligible player or reuses a still-valid
     PENDING gate (no duplicate links on repeat pings)
   - resolveBlockingGate(): returns active PENDING gate; auto-expires a dead gate and
     recreates it (user gets a fresh link). Returns null when the player was never gated
     or already VERIFIED, so normal gameplay is never falsely locked
   - verifyGateCode(): one-time use, expiry, max-attempts enforcement with fine-grained
     reasons for the game engine (NO_ACTIVE_GATE / NOT_YOUR_GATE / NO_CODE /
     INVALID_CODE / EXPIRED_CODE / MAX_ATTEMPTS)
   - requestVerificationCode(): server-side countdown (unlockAt) enforcement — the
     frontend timer is only visual; reuses an existing valid code across refreshes/tabs
   - getGateStatusByToken(): valid / verified / expired / invalid / failed / cancelled
     (+ remainingMs + countdownSeconds + codeAvailable for the page)
   - selectAdsForGate() / selectSnippetsForPage(): rotation (priority or random) with
     default provider/snippet overrides; direct-link fallback to first snippet's link
   - monetizationLink(): builds https://<host>/monetize/<publicToken>
   - recordEvent() + getMonetizationStats(): analytics foundation (totals by status,
     success rate, average verification seconds, failed attempts, gates per day)

3. BACKEND: Public Monetization Routes (apps/api/src/routes/monetization.ts)

     (records LINK_OPENED; rate limited, no auth required, no secrets leaked)
   - POST /api/monetization/:token/code — request a verification code (server countdown)
   - Mounted in apps/api/src/app.ts; dedicated monetization + code rate limiters added
     to apps/api/src/middleware/rateLimit.ts

4. BACKEND: Admin Monetization Routes (apps/api/src/routes/admin/monetization.ts)
   - GET/PUT /config           — read/update all monetization settings (validated, audit logged)
   - GET  /stats               — analytics foundation aggregate
   - GET/POST /providers, PUT /providers/:id, PATCH /providers/:id/status
   - GET/POST /snippets, PUT /snippets/:id, PATCH /snippets/:id/status
   - GET  /gates               — read-only, filterable by status/session/user/phone
   - GET  /events              — read-only event feed, filterable by type/session/user/date
   - Providers/snippets are never hard-deleted: status patch archives them (soft delete)
   - Every admin mutation writes a prisma.auditLog entry + a monetization event
   - Mounted at /api/admin/monetization in apps/api/src/routes/admin/index.ts

5. BACKEND: Game Engine Integration (apps/api/src/services/game.ts)
   - promptNumberOrTap() now runs the gate check BEFORE the next prompt: when
     turnsPlayed >= roundInterval AND turnsPlayed % roundInterval === 0 AND the player
     has no VERIFIED gate for the current round, the player receives the verification
     link, the opponent gets a "waiting" notice, and the prompt is deferred (game pauses)
   - processMessage() gate block: while a gate is PENDING this player is blocked from
     gameplay; manage/status/help/cancel/end/leave commands and the "manage" button stay
     available, everything else routes to handleGateInteraction()
   - handleGateInteraction(): code-shaped input is run through verifyGateCode(); on
     success sends verification-success + notifies the opponent ("continuing");
     MAX_ATTEMPTS / EXPIRED_CODE issues a fresh link; invalid input re-prompts
   - resumeTurnAfterVerification(): re-fetches the session (round unchanged, gate already
     VERIFIED so no re-gate) and re-prompts the correct NUMBER / TRUTH-DARE tap state
   - Gates cancelled on session finish, end, leave, expire and timeout
     (game.ts finishGame/endSession + session.service.ts expireSession/timeoutSession)
   - New bot message strings in apps/api/src/services/messages.ts
     (verificationRequired, verificationBlocked, verificationInvalid, verificationMaxed,
     verificationSuccess, opponentVerifying, opponentVerified)

6. FRONTEND: Public Verification Page (apps/web/src/app/(public)/monetize/[token]/page.tsx)
