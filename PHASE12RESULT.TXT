PHASE 12 RESULT
===============

PHASE NUMBER AND NAME
---------------------
Phase 12 — Platform Simplification & Product Sharpening
(Campaigns removed, Meta = template source of truth with sync-only provisioning, ad-network
revenue configuration removed, Ads removed, /app streamlined, anonymous contribution made
official, analytics trimmed to product data, broadcast removed, floating WhatsApp START
button) on the completed 400QUES monorepo (packages/db, apps/api, apps/web).

IMPLEMENTATION SUMMARY
----------------------
Phase 12 was carried out on the completed 400QUES monorepo (packages/db, apps/api, apps/web)
as a deliberate simplification pass: the surface area of the platform was reduced so the
product is tighter, cheaper to operate, and fully oriented around its WhatsApp-first core.
Every removal was made while keeping the live features (game engine, question pipeline,
monetization verification gates + revenue ledger, admin suite, analytics, notifications)
intact and typecheck-clean:

  - Campaigns fully removed: admin CRUD API + pages, the WhatsApp campaign delivery service,
    the campaign queue worker and webhook delivery-sync, campaign analytics series/columns,
    seed settings and nav entries. Metadata templates are no longer "submitted for approval
    to use in campaigns" — Meta is now the single source of truth and the API only syncs
    template status FROM Meta (read-only provisioning).
  - Ads removed: public display-ad endpoints (GET /api/public/ads, POST /api/public/ads/:id/click),
    the admin ad router/page, and every ad-impression/engagement counter in analytics and
    snapshots.
  - Ad-provider revenue configuration removed from monetization: providers now carry identity
    + enablement only (no revenueModel/currency/CPM/CPC/CPA rates/payouts), and the seed
    revenue.estimationEnabled / revenue.estimationMode vestigial settings were removed.
    The revenue ledger and verification-gate monetization model remain unchanged.
  - /app simplified: leaderboard (list/all-time links, /api/public/leaderboard,
    /api/public/top-contributors), profiles, badges (admin CRUD, auto-award on approval,
    seeding, /app badge display), in-app notification center + header bell, and the in-app
    search page were all removed. The app now starts at /app/categories and stays focused
    on gameplay.
  - Anonymous contribution made official: Contribution.userPhone is now nullable
    (schema + zod + moderation service + admin UI "Anonymous" label + CSV "anonymous"
    cell); the per-phone daily limit only applies when a phone is supplied. Non-anonymous
    contributions and the bot flow keep phone=identity unchanged.
  - Analytics trimmed to product data: the /users and /top admin endpoints, getUserAnalytics,
    getTopAnalytics, the topContributors aggregation, the per-day "users" timeseries column
    and the users CSV dataset were removed; the web BI dashboard dropped the Users tab and the
    Top-contributors card. Phone masking helpers tied to the removed surfaces were deleted.
  - Notification broadcast removed: the admin POST /api/admin/notifications/broadcast endpoint,
    the broadcastNotification() service, the "broadcast" BullMQ job + batch worker and the
    broadcast-resume cron are gone; the admin notification center remains (list/unread/read).
  - A floating WhatsApp button ("Start on WhatsApp") was added site-wide via wa.me with the
    pre-filled START command, and all public flow copy now teaches the START command
    (aliases start/new/play/create in the bot's command registry).
  - A strict BUILD-ONLY approach was followed: no tests, no servers, no WhatsApp/Google-AI/
    game/live-DB/external-service runtime verification. Only prisma generate and TypeScript
    typechecks were run (db / api / web: 0 errors each). Lint was not run because the repo
    has no ESLint configuration (pre-existing condition).

EXISTING FEATURES DISCOVERED
----------------------------
  - Monorepo: packages/db (Prisma 5.22.0, seed), apps/api (Express 4, Zod, BullMQ, node-cron,
    socket.io, multer+sharp), apps/web (Next.js 14 App Router, Tailwind, Radix, TanStack Query).
  - WhatsApp-first product: phone number is the identity; the game, contributions, reports,
    category requests and notifications are phone-scoped.
  - Question pipeline: DB candidate search BEFORE Google AI; deterministic exact-duplicate
    check; AI classification EXACT_DUPLICATE | VERY_SIMILAR | UNIQUE; VERY_SIMILAR routes to
    manual review; UNIQUE can auto-approve when contribution.autoApprove is enabled.
  - Monetization = verification/ad links only (no payments/premium/subscriptions); RevenueLedger
    records per-verification revenue with ESTIMATED vs CONFIRMED trust split.
  - Meta WhatsApp Cloud API integration: webhook ingestion (signature-verified), message send
    service, and metadata templates synced from WhatsApp's template endpoint.
  - Recovery/session-sweep/retention/snapshot crons run under Redis locks; notifications have a
    channel/status lifecycle with a delivery worker.
  - Orphaned-but-now-unused data models were discovered (see DATABASE / SCHEMA CHANGES): the
    Badge/UserBadge, Campaign/CampaignDelivery and Ad rows and related enum values have no
    remaining consumer after this phase's removals.

FEATURES ADDED
--------------
  1. Meta-as-source-of-truth template sync (apps/api/src/services/template.service.ts +
     routes/admin/whatsapp.ts + /admin/whatsapp templates tab): templates are now synced one-way
     FROM Meta via POST /api/admin/templates/sync (audited as TEMPLATES_SYNCED). The admin tab
     shows four read-only stats (total / draft / active / submitted / approved / rejected /
     archived / synced) with a "Sync from Meta" button and a read-only template table. The ability
     to create/update/delete/submit templates through the admin UI was removed (provisioning is
     done on Meta's side; 400QUES only reflects Meta state).
  2. Floating WhatsApp START button (apps/web/src/components/whatsapp-float.tsx): a fixed
     bottom-right green button on every page that deep-links to wa.me/<whatsapp.number>?text=START.
     It renders only when the whatsapp.number public setting is configured and text-prefills the
     bot entry command START (aliases start/new/play/create).
  3. Anonymous contribution support end-to-end: schema-level nullable userPhone,
     optional userPhone in the public zod schema, moderation accepts null, the per-day limit is
     skipped without a phone, the public contribute form marks the field "(optional) — leave
     blank to contribute anonymously", admin approval/console renders "Anonymous", and the
     contributions CSV emits "anonymous" for null phones.

SECURITY CHANGES
----------------
  - Reduced public surface: the player-facing API no longer exposes profile, leaderboards,
    public notifications or ad-click endpoints — fewer vectors, less sensitive data on the wire.
  - Anonymous contributions cannot be tied to a phone, so the per-phone daily contribution
    limit (spam control) is intentionally bypassed for anonymous submissions; moderation
    (AI + duplicate check) still gates every anonymous row before it can reach the library.
  - Admin user-management endpoints (ban/unban/role) were removed along with the feature; the
    remaining admin routes stay behind the existing admin JWT + role gate.
  - All existing protections remain in force: admin JWT + role checks, phone-scoped public
    actions, non-anonymous contribution/report daily limits, rate limits (auth, code,
    contributions, monetization, public, webhook), helmet + compression, request-id
    propagation, and the admin audit log on every mutation.
  - No secrets were added to the repository; .env stays git-ignored, .env.example committed.

  auto-reject, VERY_SIMILAR manual review, config-gated auto-approve, monetization via
  verification links, liquid-glass green/blue/orange design.)

      product story was dropped; revenue/monetization BI stays.
    - Same single container story as before: plan for one process mode running both API + worker
